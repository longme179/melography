## Diagnosis (verified, not guessed)

Reproduced the owner's exact error against the **minified production
bundle** (`npm run build` on main @ 22e0566, grep of
`X.width=Y.width` assignments): the bundle contains exactly one
unguarded pair `p.width=v.width` plus one guarded `d.width=W.width`,
and the context proves the mapping:

```js
ae.putImageData(new ImageData(W.rgba,W.width,W.height),0,0),v&&g&&{
  n(2,p.width=v.width,p), …be.putImageData(new ImageData(v.rgba,…
```

- `p` = `originalCanvas`, `v` = `original`, `W` = `active`, `d` = `canvas`
- Source: `Viewport.svelte` blit() — `if (original && edited) {
  originalCanvas.width = original.width; … }`
- The compare canvas is `bind:this`-bound only while its
  `{#if $compareOn && original}` block is mounted; `compareOn` defaults
  to **false** (stores.ts), and renderPass loads `original`
  unconditionally. Net effect: **every render pass with compare off
  (the default) threw a TypeError** — AFTER the edited image had already
  drawn (line order), which is exactly the owner's symptom: the preview
  works, the banner spams.
- Pre-existing (the same structure existed pre-A1; confirmed by diffing
  dbef47c), not an A1 regression — but equally not fixed by A1.

## Fix — one class, not one line

1. **`ui/src/lib/blit.ts` (new)** — the single RGBA→canvas path
   (`putRgba`, `blitFrame`). Parameters are `| null | undefined` by
   signature: unbound canvas, missing frame, non-finite/non-positive/
   fractional dims, or a buffer whose length ≠ w·h·4 are **typed
   no-ops** that leave the caller's previous pixels untouched; the 2d
   context is acquired BEFORE any resize so a null context also leaves
   the canvas untouched. tsc --noEmit now actually checks this code
   (it lives in .ts, not .svelte).
2. **Viewport.svelte**
   - blit() = two `blitFrame` calls + layout; no direct canvas writes.
   - Compare canvas mounts whenever an `original` frame EXISTS and is
     CSS-hidden (`.split-clip.off { display:none }`) while compare is
     off — the element lifecycle now matches the data lifecycle, so
     blit always has a bound canvas AND toggling compare shows the
     already-drawn original instantly (was: blank left half until the
     next parameter commit — same root cause, separate symptom).
   - `$: if (originalCanvas && original) blitFrame(...)` — the canvas
     binds on the Svelte flush AFTER the pass that loaded `original`;
     this draws it the moment it exists (covers both first mount and
     image/dim changes).
   - `imageOpen → false` clears `edited`/`original`/`originalKey` —
     stale frames could previously drive layout() against an unmounted
     canvas on window resize after close.
   - renderPass catch banners only while an image is open — a pass
     failing because the image was CLOSED mid-render (no session on the
     Rust side) must not pop the banner at the home screen.
   - `canvas`/`originalCanvas`/`container` typed `| undefined`;
     layout()/onPointerMove/onPointerDown guarded.
3. **Filmstrip.svelte** — `rgbaToDataUrl` routes through `putRgba`
   (single path; a truncated frame now yields an honest empty strip
   instead of a canvas exception).
4. **`scripts/ui_blit_smoke.mjs` (new CI gate)** — compiles the REAL
   blit.ts with the workspace's own esbuild (no new dev deps), runs it
   against stub DOM elements: unbound canvas (the exact crash), missing
   frame, truncated buffer, degenerate dims (0/-2/NaN/2.5/∞), null 2d
   context, and the well-formed success path (resize + exactly one
   putImageData carrying the frame's exact bytes). Section 2 is a
   code-only (comments stripped) scan forbidding direct
   `canvas|originalCanvas .width/.height =` assignment anywhere in
   ui/src outside blit.ts — the crash class cannot be reintroduced at a
   call site without failing CI.
5. **Types** — `PreviewFrame.rgba: Uint8ClampedArray<ArrayBuffer>`
   (ipc.ts) + matching params in blit.ts/Filmstrip: TS 5.7+ typed-array
   generics are what lib.dom's `new ImageData(data, w, h)` requires;
   the old code only typechecked because tsc never looked inside
   .svelte files. Lockfiles agree (npm + bun: typescript 5.9.3).

## Notes for review

  compare is off (display:none). It is out of the a11y tree and hit
  testing exactly like the old {#if} removal; it holds the last-drawn
  original so toggle-on is instant.
- No error-inventory row: this PREVENTS a JS TypeError at the blit
  boundary; it is not an AppError code (banner text was the generic
  error.title carrying the raw exception).
