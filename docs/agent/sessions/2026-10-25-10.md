## What was done (and what it found)

### Memory budget — two real bugs, not just a test

The budget gate (`memory_budget.rs`, 49.8 MP end-to-end through the
real `cmd_film_apply`) initially measured **1835 MiB** — under the
2 GiB bar but with only 213 MiB headroom, which triggered the
investigation the budget exists for. Phase-by-phase VmHWM/RSS probing
(since reverted — the probes were scaffolding) localized the peak:

* **Bug 1 — the pre-tone f32 buffer survived its own replacement.** The
  tone leg's `match &opts.tone { Some => (toned, …), None => (ap1, …) }`
  shape conditionally moves `ap1`; in the Some path the old buffer
  stayed allocated through render+encode (RSS 1170 MB after tone where
  ~585 was expected). Fix: move `ap1` INTO the match (`match (&opts.tone,
  ap1)`) so each arm owns it. Peak: 1835 → 1265 MiB.
* **Bug 2 — everything held for one fingerprint.** `decoded` (a second
  full-res image), the input file bytes, `ap1`, `working`, and the
  whole output file (slurped for the report hash) were all alive to the
  end. Fix: hoist fingerprint/encoding/dims out of the decode buffer
  and drop it before tone; drop `ap1`/`working` as their successors
  exist; chunked `sha256_file` (1 MiB) instead of slurping; two
  full-res `ap1.clone()`s eliminated (one was in the tone None arm, one
  in the no-LUT path).

Final: **1265 MiB peak, 38% headroom**, per-OS honesty (Linux VmHWM
exact; Windows PeakWorkingSetSize via psapi FFI — no new crate; macOS
sampled lower bound, printed as such).

### Kill-during-export — the battery that failed its own sensitivity test

First version (spawn + random-delay kill, mirroring `durable_kill.rs`):
the atomic code passed, but so did a **mutated direct-write TIFF
encoder** — 5/5 runs. The encoders' write phases are single-digit-ms
slices of a ~100 ms loop; random kills never landed inside them. That
battery would have provided green-checklist theater, not protection.

Rework: the child announces each encode with one `W` byte on stdout
(`--nocapture` — the default libtest capture silently ate the first
attempt's protocol, debugged via the harness's own `\n` leaking
through); the parent kills 0.2–3 ms after the first `W`, deterministically
inside the write window; images enlarged to 1280×960 so every encoder's
write phase is tens of ms even in debug. Validation: atomic 6/6 pass;
direct-write mutation **caught 4/4** (round 1 each time). All four
encoders now publish atomically (`atomic_write_durable_with` streaming
variant added to `core::durable` — `decode_file`/`encode_png16/8`,
`jpeg_u8`, `jpeg_u8_with_icc`, `tiff_u16`), and the battery asserts the
full contract: complete-or-absent, litter cleanup, retry-to-same-path.

### Fuzz battery

`fuzz/` standalone crate (workspace-excluded like the spikes; nightly +
libFuzzer 0.13.0 pinned): `decode_image` (new `decode_bytes` — the same
S0 sanitization as `decode_file`, equality unit-tested; >300 MP bomb
path exercised for real, 8 MP harness clip documented in-target),
`cube_parser`, `sidecar_json` (parse + migrate + re-serialize), and
`manifest_json` (parse + `vet`). Seeds: 30 cube adversarial cases +
deterministic Pillow-generated tiny images (10) + schema-true JSON (5),
via `scripts/gen_fuzz_corpus.py`. Local bursts: 0 crashes on all four;
decode alone 156,751 execs/46 s. CI `fuzz-burst`: 30 s/target, scratch
corpora, crash artifacts uploaded on failure.

### Secret scan + provenance — both found real gaps immediately

`secret_scan.py` (16 patterns × 335 tracked files; the `.gitignore`
policy made executable: mandatory lines present + nothing tracked that
the policy ignores; allowlist entries carry reasons — the scanner's own
pattern source is the first entry). `provenance_check.py` (every binary
asset needs a sibling or directory record, **sha256-verified**; both
sibling naming conventions and both directory-key depths supported
because the repo's existing records use a mix). Found: 2 placeholder
icons with no provenance (records written with honest M0/M1 origins) +
the fuzz corpus seeds (records generated).

### Error-state inventory — and the two codes it caught

`ERROR_STATE_INVENTORY.md` (38 codes × taxonomy × EN/VI × surface ×

The gate's first runs caught **`io.encode` and `lut.encoding_mismatch`

### Cache budgets + status-bar hit-rate

`cache.rs`: the LUT resolution cache is now a byte-budgeted LRU
(quarter of `Settings.cache_budget_mb`, floor 64 MiB; oversize LUTs
served-not-retained), the preview slot enforces its budget (an image
larger than the budget renders but is not retained — "cache off" in the
viewport, never a silent overrun), budgets update live from Settings,
and `cache_stats` + the S2 status bar surface the measured hit-rate
(`cache 87%` / `đệm 87%`, or "cache off"). 7 new unit tests; the old
bare `Option<RenderCache>` and unbounded `HashMap` are gone.

## Environment notes (reproducibility)

Sandbox reset again: Rust 1.99.1 + nightly reinstalled, `npm ci` for
the UI. **The sandbox has no webkit/gtk headers and no sudo** — the app
crate was checked/tested headless via a local-only pkg-config shim

fuzz crate builds/tests clean under nightly without the shim.

## Deviations / decisions worth flagging to the owner

* The kill battery's anchoring method (progress pipe + enlarged test
  images) replaces the "obvious" copy of the save battery — the
  mutation-test evidence for why is in the report and the battery's
  module docs.
* The decode fuzz harness clips 8–300 MP inputs instead of materializing
  them; the rationale (and what covers that band instead) is documented
  in the target header.
* `bundle.active` flipped to true — this enables LOCAL installer builds
  only; nothing in CI or RELEASING changed. If you prefer it stay false
  until M5, one line reverts it (the scripts would then need
  `--bundles` to bundle, which they already pass).
* The two build scripts for Windows/macOS are syntax- and logic-verified
  on Linux only; their first real runs are expected on your machines or
  the M5 workflow (noted in BUILDING.md).
