## 3. Session-model slice delivered (issue #24 core)

1. **`core::durable`** — the single durable-write primitive
   (`atomic_write_durable` + `sync_dir` + `clean_stale_tmp`), replacing
   THREE private copies (lut library, ai manager, presets). Found and
   fixed an honesty gap while unifying: presets' old `atomic_write`
   opened the temp file read-only for fsync and SILENTLY IGNORED the
   Windows failure — Windows recipe saves shipped without any real
   sync.
2. **Kill battery** (`crates/core/tests/durable_kill.rs`): the test
   binary re-executes itself as a child writer; the parent SIGKILLs at
   randomized 2–30 ms points ×6 rounds and asserts the recovery
   contract — published file always complete (old or new version),
   never torn; read-back verification in the child; litter cleanup is
   surgical. This IS the PLAN M4 exit criterion "kill during save
   green", running on all 3 OSes in CI.
3. **Undo/redo**: `RecipeSnapshot` (film + tone + LUT stack),
   push-before-mutate in `set_film`/`set_tone`/`set_lut_stack`, bounded
   100-step history, redo cleared by new mutations, history reset per
   session (open/close). Commands `undo`/`redo` + `can_undo`/`can_redo`
   in state; UI: toolbar buttons + Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y +
   panel re-fetch after every history jump. Panels use commit-level
   `on:change` events, so history granularity = one entry per
   interaction, not per slider tick.
4. **Autosave**: debounced 900 ms at the single settle point
   (`refreshState` after every mutation path); the dirty badge is the
   indicator (never a modal, never a toast); explicit Ctrl+S cancels
   the pending timer; timer cancelled at unmount.
5. **Open-time litter recovery**: `clean_stale_tmp` on the sidecar path
   in `open_image` — a killed save's leftovers never block opening.
