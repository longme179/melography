## Root cause (confirmed by code reading + all of the above evidence)

**The WGSL respond stage replicated the monochrome density into channels
1/2 (`d = vec3(d.x)`) while the CPU writes `[D, 0, 0]`** (emulsion.rs
initializes `d = [0.0; 3]` and the `layers = &[0]` loop fills layer 0
only). The print stage reads layer 0 only — so the FINAL image was
unaffected (grain-off parity 1.19e-7; the A2.4 `film_pixel_parity`
battery, which compares post-print output, stayed green) — but the grain
σ(D) reads the density-plane LUMINANCE `0.25·d₀ + 0.5·d₁ + 0.25·d₂`:
the CPU σ saw **0.25·D**, the GPU saw **D**.

Why classic-monochrome-400 only, and why config-invariant: its `m_exc`
sums RGB into layer 0 but the C3 anchor averages the log-exposures of
ALL THREE layers — two of them zero (log10(1e-12) = −12) — so
`exposure_scale ≈ 1.6e6` saturates the H&D shoulder: **D = 1.84 flat
across the whole test image** (legB's printed dmax = 1.8400 exactly =
d_min 0.06 + curve max 1.78; dmin 0.0 = the ch1/ch2 zeros). A flat
saturated density field is invariant to vignette/veiling/tint — hence
the identical 3.924e-2 worst at the same pixel in every lens config.
The σ bias is a CONSTANT: σ(1.84) = 0.028 vs σ(0.46) = 0.0428 → every
mono grain amplitude biased −35% on the GPU (0.028/0.0428 = 65%);
gathered at the pixel with the largest local grain draw → 3.924e-2.
Quantitatively consistent end to end.

## Fix (this session)

- `crates/gpu/src/film_pixel.rs` — respond(): DELETED the mono
  replication; the shader now mirrors the CPU plane exactly ([D, 0, 0]).
  The print-side replication (`out = vec3(out.x)`) stays — the CPU print
  replicates too ("Monochrome: replicate layer 0").
- `crates/film/src/gpu_chain.rs` — brace structure repaired (Leg C now
  lives inside `mono_composition_legs`, renamed from
  `mono_composition_legs_a_b`); Leg C gained an assert (worst ≤ 1e-3 on
  the pre-print respond plane) — a standing gate for exactly this
  print-clamped failure class that no post-print gate can see; the doc
  comment records the full root-cause story.
- `crates/gpu/src/spatial.rs` — cellDensityLum comment documents the
  mono plane contract (0.25·D on both sides).

**CPU behavior deliberately unchanged** — zero render-output change.
The mono model questions the bug exposed are documented as
owner-decision follow-ups in FILM_MODEL §G: (1) the C3 anchor averaging
inactive layers' logs (saturates mono's H&D — the grain field ends up
density-uniform on ordinary images), (2) the σ-curve knots 1.2/2.0
unreachable through the 0.25·D luminance read for mono — same
authoring-artifact family as the stock's psd_slope (session 17).
