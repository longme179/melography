## Design (validated before any Rust — the A2.2/A2.3 discipline)

Repo-external cross-check (`~/my-project/scripts/a24_gpu_wiring_check.py`):

| Check | Result |
|---|---|
| Vignette f32 (per-column/row LUTs, cos/pow in f32) vs the f64 CPU formula, 4 FOVs × 4 amounts × 200k draws | max \|Δ\| = **2.2e-7** (4500× inside the 1e-3 budget) |
| `k = 0` exact identity (`cos(θ)^0 = 1`) | exact on both sides — dispatch skipped |
| Veiling blend through the halation h+v structure (f32 passes + `(1−α)src + α·G` combine) vs the CPU f64 conv+mix, σ ∈ {1.3, 6, 24} px, s ∈ {0.03, 0.09, 0.3} | max \|Δ\| = **1.1e-7** |
| Halation blend-flag bit compatibility: `src + α·(halo − 0·src)` vs `src + α·halo` | value-identical for all finite inputs; bit-identical whenever the result is nonzero (only the sign of zero may differ — invisible to every gate) |

Structural decisions:

1. **Veiling reuses the halation dispatch** — the CPU formulas are the
   same separable h+v convolution with a different combine
   (`(1−s)E + sG` vs `X + αG`), so the V shader gained a per-channel
   blend mode in the previously-unused packed params slot [0]. Halation
   payloads pack 0 → the additive expression and bytes stay identical
   (the compatibility check above). No new convolution kernel.
2. **Vignette is a new tiny kernel** — positions as CPU-resolved f64→f32
   per-column/per-row centre-offset LUTs (the CI rounds 3–7 lesson:
   absolute film coordinates never enter the shader).
3. **film_pixel stage split** — the fused kernel's three sections
   (excitation / response / print) became stage-flagged dispatches
   (flags bits 4–6) of the SAME shader functions. f32 buffer round-trips
   are lossless ⇒ split ≡ fused holds bit-exact by construction — and is
   GATED bit-exact (a divergence would be a stage-boundary bug, not a
   tolerance matter). The spatial kernels interleave at exactly the CPU
   strip positions: vignette → veiling → excitation → halation →
   response → grain (FULL model) → print.
4. **Persistent context** — `GpuContext` (device + queue + all five
   pipelines compiled once) in a process-wide slot; `AdapterPolicy`
   (`Auto` score = device-type rank ×100 + backend rank, documented
   tie-break; `ByFingerprint` for the Settings pick, honest error when
   absent); uncaptured device errors parked in a diagnostics slot
   instead of panicking the render thread. The A2.3 standalone `run_*`
   keep their per-call acquire (parity-harness pattern, unchanged
   behavior); new `run_*_on` variants take the shared context.
5. **Fallback contract (app `GpuRuntime`)** — GPU off in settings → CPU;
   no adapter → CPU for the session with the reason surfaced; pinned
   adapter absent → CPU with the reason (NEVER a silent wrong-adapter
   render); 3 consecutive failures → session circuit breaker, re-armed
   by an adapter change or restart. Every frame that misses falls back
   to the A2.1/A2.2 threaded fast-grain CPU leg — the preview never
   blocks and never surfaces a GPU error to the user.

## Known trade-offs (honest)

- The full-chain gate is 2e-3, not 1e-3: each constituent kernel holds
  1e-3 standalone; composition through the nonlinear H&D response can
  locally amplify. The measured per-kernel numbers (A2.3: 1e-6–1e-5
  typical) suggest the real composition error sits far below 2e-3; CI
  prints every number — if the evidence supports tightening, that is a
  one-line change with numbers behind it.
- GPU buffers are allocated per dispatch (correctness first); a
  persistent ping-pong buffer pool is a measured follow-up if the perf
  leg shows allocator overhead.
- `stock_thumbs` also routes through the GPU leg now (same render
  path); thumbnails are small enough that either backend is fine.
- A4's diagnostics view (probe timings, render telemetry, opt-in
  export) remains open — the policy + picker + honest rows shipped.

## The bug the gate caught (CI round 4 — the headline of this session)

The full-chain parity gate ran for real on CI's Metal adapter (Apple
Paravirtual device) and FAILED with worst |Δ| = **3.9e-2** on
classic-monochrome-400 (3.6–3.7e-3 on the warm-stock cases) — 20× the
composition budget. Diagnosis: **the M2 CPU chain never consumed the
halation output.** `render_strip` computed `plane_b = X + H(X)`
(`apply_halation`), then ran the H&D response on `plane_a` (the
UN-halated excitation) and let `grain.apply(plane_a, plane_b, …)`
overwrite the halated rows — halation has been visually dead in every
CPU render (previews AND exports) since M2, while every stage-level
gate stayed green (they test `apply_halation` directly; no gate pinned
the chain's internal dataflow; the determinism/tiling gates are
self-comparing).

The fix (this PR): the response consumes `plane_b` (the halated
excitation, FILM_MODEL §C2→§D — "X_halo = X + H(X)" feeds the H&D
curves), grain reads the response output from `plane_b` and writes
`plane_a`, print reads `plane_a` → `plane_b`, and the output loop
copies `plane_b`. All §L invariants hold by construction (the strip
executor is shared; tiled≡mono and determinism are unaffected — the
existing tests are invariant-based, none pinned the buggy bytes).

This is exactly the class of defect the A2.4 gate was built to catch —
a GPU mirror that fed halation into the response (per the spec)
diverged from a CPU reference that silently dropped it. The gate
caught it on its first real run.
