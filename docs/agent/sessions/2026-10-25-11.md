### The "Film Room not good yet" diagnosis — three real defects, verified

Root-caused against `main` @ 5f2d34f before writing a line of plan:

1. **Full-res renders per slider commit.** `FilmLab.svelte:25` calls
   `render_preview` with `maxDim: 0`; `render.rs::downscale_ap1` treats
   0 as the identity → the film chain runs at full source resolution
   (the M2 §4 baseline: 3.4–4.4 s at 3.1 MP preview scale — full-res
   is ~8× that on 24 MP) and produces a wire frame up to ~100 MB that
   the caller then *discards* (`.catch(() => {})`). The Viewport, by
   contrast, renders bounded (256..2560 from window size).
2. **Cache poisoning across sizes.** `compose_preview`'s cache key
   covers stack+film+tone but *not* `max_dim`, so a full-res render is
   served to every later bounded request (or the slot is dropped by
   the budget → permanent misses).
3. **No render on stock select + swallowed commits.**
   `selectStock()` updates state but never requests a render → picking
   a stock shows no visual change until a slider moves; the `busy`
   gate drops rapid slider commits with no last-wins coalescing.

These three explain both owner complaints (Film Room quality; slow
preview) — fixes + edge cases are specified in PLAN M5-A A1.

### LUT sourcing research (`luts.md` §6)

Two tiers, license-clean by construction: **Tier 1** self-generated
(camera-log→Rec709 baked from published transfer functions — LogC3/4,
S-Log3, V-Log, CLog3, F-Log; PFE-style looks from our own print stage;
vendor LUT files never bundled, dev-time validation only) and
**Tier 2** license-gated externals (G'MIC CeCILL; Pat David's set —
license to verify, canonical page unfetchable this session, recorded as
a to-verify item; YahiaAngelo MIT conversions; slay CC BY 4.0) through
the existing manifest/provenance gate, `LICENSES-LUTS.md` per entry.
Rec709-confusion guard documented (rec709-gamma2.4 ≠ sRGB ≠
display-linear; encoding contract enforced; UI never calls these
"sRGB").

### lightcraft (`comparables.md` §6)

Apache-2.0/MIT dual — the first comparable whose license permits
code-level reuse with attribution (ADR-0003 vetting applies). Borrowed
into the plan: background render worker pool; the public ~4 ms/24 MP
slider re-render on wgpu compute (the existence proof calibrating our
A2.3 GPU target); preset-Amount pattern (extend LUT intensity
semantics to stocks). Confirmed differentiation: it ships no LUT
support and no film emulation.

### GPU vendor support (PLAN M5-A A4)

Scoped from research + existing `crates/gpu` (enumerate/probe exist;
the app only has a `gpu_enabled` bool today): adapter picker (Auto =
discrete > integrated > software with documented vendor tie-break; +
manual per-adapter), backend order Vulkan → DX12 → Metal → GL with
llvmpipe last-resort labelled "slow (software)", device-loss recovery
(eGPU unplug; auto-disable after N failures, persisted), mixed-GPU
wrong-adapter reports (wgpu/Steam) as the documented known-issue
matrix, and a local-only diagnostics view (R-PRV-1 stands — no
telemetry).
