## What was done (defect by defect)

### 1 · `maxDim: 0` = full-res render (the P0)

- `render.rs` now owns the semantics: `MAX_DIM_MIN/MAX_DIM_MAX` (256/2560)
  + `resolve_max_dim(fallback, requested)` — `0` (the legacy "unbounded"
  sentinel) → `Settings.preview_max_dim`; in-range passes; anything else
  → typed `render.max_dim_out_of_range` (`error.rs` model, EN/VI catalogs,
  `ERROR_STATE_INVENTORY.md` row — `error_inventory.py` PASS at 39 codes).
- Applied at the ONE boundary that matters: the `render_preview` and
  `original_frame` commands (compare parity: hold-B can never fetch a
  differently-scaled frame). `compose_preview`/`compose_original` stay
  permissive — trusted internal callers compose 48–256 px thumbnails
  through the same code.
- `set_settings` now clamps before assign+save (`settings.clamped()` made
  `pub(crate)`): previously a hand-edited IPC payload could write an
  out-of-range `preview_max_dim` into the *in-session* fallback (load
  clamped, save didn't) — the exact hole the sentinel falls back into.
  `resolve_max_dim` re-clamps the fallback as defense in depth.
- FilmLab.svelte no longer invokes `render_preview` at all (the
  `.catch(() => {})` ~100 MB discarded frame is gone with it).

### 2 · Cache key omitted `max_dim` (slot poisoning)

- New `preview_key(base, stack, film, tone, max_dim)` — one place that
  computes the slot key; `compose_preview` consumes it. Identity tone
  still folds out (unchanged semantic, now pinned by a test).
- The slot now caches the **bounded** preview image on BOTH legs: the film
  leg always rendered at preview scale (unchanged); the no-film leg's
  full-res LUT output is downscaled *once* before caching instead of
  per-hit. Consequences, all verified by tests:
  - a bounded request can never be served a differently-scaled slot frame
    (frame-size explosion / stale grain scale are both dead);
  - the hit path is a blit — no per-hit re-filter of a full-res image;
  - ≥35 MP sources finally fit the budget (a 2560-bounded frame is tens
    of MB; the full-res render blew the 512 MiB default and *never*
    cached — the honest-degradation "every render is a miss" case).
  - budget-exceeded frames stay un-retained (contract unchanged).
- Known trade-off (documented in PLAN): a viewport-size change with no
  film leg re-renders once (was a hit + downscale). Coalescing bounds the
  resize storm to that single final render; the film leg already behaved
  this way — now it's correct on both legs.

### 3 · Stock select never re-rendered; busy gate swallowed commits

- FilmLab takes `onChange` like every other panel (BasicPanel/
  GrainHalationPanel precedent); App wires it to `onLutChanged` →
  `viewport.refresh()` — **one render path**, stock select included.
- The `busy` gate is deleted: commits always execute; renders coalesce in
  the viewport instead of being silently dropped.
- `Viewport.refresh()` is now last-wins coalescing: one pass in flight at
  a time; mid-render requests collapse into a single queued re-run that
  reads the *latest* `maxDim` + params when it starts (resize mid-render
  re-renders at the new bound). A request queued during a *failing* pass
  is drained in `finally` — the last state still renders once, with no
  retry loop (a retry requires a fresh queued request).
- Original-frame reuse: the compare "original" is re-composed only when
  `(imageKey, dim)` changes (App passes `$state.sourcePath`), not on
  every slider commit — `compose_original` is uncached full work and was
  paid per refresh.
- Compatibility sweep found one more UI caller: `Filmstrip.svelte` pulled
  its "original" glyph via `originalFrame(96)` — below the new bound. It
  now asks for 256 (minimum bound; the browser downscales for display,
  crisper on HiDPI). `stock_thumbs` (48..256 internal clamp) and the
  internal 160 px recents/batch thumbnails are trusted non-command
  callers and stay as they are.

### Tests (every A1 defect class)

- `max_dim_resolves_at_the_command_boundary` — sentinel fallback (proved
  read, not hardcoded: non-default 1024), inclusive bounds, out-of-range
  → `render.max_dim_out_of_range`, drifted fallback clamps.
- `preview_cache_key_separates_viewport_sizes` — different `max_dim` →
  different keys on both legs; identity tone folds out.
- `bounded_request_never_receives_a_larger_cached_frame` — 512-bounded
  compose then 256 request → 256×192 frame (not the stale 512 one), miss
  counted, slot replaced with the 256-bounded artifact.
- `film_leg_compose_is_bounded_by_max_dim` — the reported "Phòng phim"
  defect: 600×400 source through a real film chain at 256 → 256×171 frame
  + slot; different bound → miss + re-render at that scale.
- Updated `preview_cache_hits_and_invalidates` (slot key = `preview_key`)
  and `command_flow.rs` (same) for the folded key.
