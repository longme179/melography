## Design (cross-checked in Python before any Rust was written)

Sandbox has no cargo — the strongest local verification is a
repo-external Python cross-check
(`/home/z/my-project/scripts/a23_grain_wgsl_check.py`) that ports the
CPU `RandStream`/`cell()` (f64) and the planned WGSL cell path (f32,
wrapping u32) side by side:

1. **Presence threshold**: the CPU decides presence with
   `f64(draw) < p·2^32`; the GPU packs the exact u32 threshold
   `ceil(p·2^32)` (+ an `always` flag for p·2^32 ≥ 2^32). Verified
   equivalent on 200k random draws + edge cases — **presence decisions
   match bit-for-bit**, no f64 on the GPU needed.
2. **Draw order** (the bit-portable contract): jitter ×2 → presence →
   radius pair (cos half) → (n0,n1) pair → (n2,_) pair = 9 draws,
   exactly `GrainField::cell()`'s sequence. Jitter uniforms are
   24-bit → exactly representable in f32 → **bit-identical**; radius /
   amplitudes agree to ≤ 2.2e-9 (pure f32 rounding noise).
3. **k rule parity**: `clamp(round(mmpp/6 µm), 1, 4)` reproduced for
   the preview/mid/native scales used by the parity gates.
4. **Boundary-flip harmlessness**: the bump profile is C¹ at t = 1
   (inclusion flips contribute ≈ 0 weight) and the gather reach
   exceeds every possible radius by a full cell (window-edge floor
   flips select cells that contribute exactly 0) — f32-vs-f64
   positioning noise cannot cause parity outliers, only tolerance
   noise. The mono amplitude uses `chol[0]·g[0]` only (rho is ignored
   for mono layouts on the CPU — the shader must not "helpfully" use
   the full Cholesky row).

A second script (`a23_wgsl_lint.py`) lints the three shaders for
balance / hex-literal suffixes / call-target existence before CI's
naga gate runs.

   `film_pixel_types` pattern): `GrainGpuParams` + `HalationGpuParams`
   + packed-f32 layouts (u32 quantities as `f32::from_bits`, recovered
   via `bitcast<u32>` — exact for any u32, unlike a value cast) +
   layout unit tests.
2. **`crates/gpu/src/spatial.rs`** (wgpu feature): three WGSL compute
   kernels — **grain gather** (the FULL §G model per pixel, k×k
   pixel-area supersampling, σ(D) read bilinearly at cell centres with
   the CPU's out-of-frame-zero semantics, never-negative clamp) and
   **halation h+v** (separable per-channel unit-DC taps + α, zero
   padding, inactive-channel pass-through matching the CPU skip
   exactly). `run_grain`/`run_halation` follow the film_pixel harness
   idiom (fresh device per call; the app-wiring step owns the
   persistent context). naga offline validation tests for all three
   shaders (run on every OS — the `log10` lesson).
3. **Bridges**: `GrainField::gpu_params(frame, w, h)` (calibrated
   a_norm, Cholesky, u32 presence threshold and the k rule resolved on
   the CPU in f64) and `gpu_bridge::pack_halation_gpu_params(em, w, h)`
   (activity = active layer ∧ α > 0 ∧ non-identity kernel — the CPU
   `apply_halation` skip condition, so sub-pixel halos stay skipped on
   both sides).
4. **`crates/gpu/tests/spatial_parity.rs`**: CPU↔GPU parity ≤ 1e-3 —
   all 5 shipped stocks (color + mono) for grain at k=4, plus a tall

   all stocks + attenuated + preview-scale + off, and dispatch

5. **`crates/gpu/tests/spatial_perf.rs`** (#[ignore]d, owner-run

## Scope honesty (what this PR deliberately does NOT do)

The kernels are parity-gated library pieces, not the app integration:
no persistent GPU context, no preview-pipeline wiring, no adapter
selection policy (that is A4), no Settings toggle. The CPU path stays
the reference for every consumer today; export/CLI are untouched. The
next plan step composes the pixel kernel + spatial kernels into the
GPU preview leg and measures against the re-pinned §4 budget on the
owner's machine.

## CI saga (the no-cargo discipline, rounds 1–4)

- **R1 (parse)**: E0753 — one `///` line of the `GrainGpuParams` doc
  comment mistyped as `//!` (inner doc after the first item); everything
  downstream of the parse error was masked. Fixed in 02c8765.
- **R2 (fmt + one test)**: pure rustfmt joins — the four
  `ctx.device.create_buffer_init(...)` statements want chain breaks
  (chain_width 60), the grain-case eprintln goes vertical (args > 60)
  while single-string eprintlns collapse, and `Adjustments { .. }`
  struct literals stay vertical (struct_lit_width 18); plus the
  halation taps fixture used `i·0.01` which is not representable in
  f32 (30·0.01 = 0.29999998 ≠ 0.3 — the layout test compares bits).
  Round 2 also carried the good news: **all 3 naga validations PASS**
  and the workspace compiled including every gpu test target. Fixed in
  303dc80.
- **R3 (a real parity failure — the interesting one)**: on the Metal
  adapter, halation parity was 2.384e-7 (all cases) and grain k=4
  passed at 1.3–2.1e-4, but the k=1 native-scale case (48×4000,
  6 µm/px) failed at **2.284e-3 > 1e-3**. Diagnosis: absolute film
  coordinates are ~18 mm where f32 eps (1.07e-6 mm) is a third of a
  grain radius — sample/cell positions each carry ~1.5e-6 mm of
  rounding, the bump weights disagree with the CPU by ~4e-4 relative
  per cell, and k=4 had merely been hiding it by averaging 16
  sub-samples (2.3e-3/16 ≈ 1.4e-4 — exactly the observed k=4 level).
  Reproduced and fixed in a Python f32 simulation of the same gather
  (`scripts/a23_k1_precision_fix.py`): **cell-unit compensated
  arithmetic (two-sum residuals + fma product residual → ~1e-11-cell
  accuracy, the hi-part cell subtraction exact under Sterbenz) +
  INTEGER cell-index guard ranges for the cell-centre density read**
  (the CPU's exact f64 bilinear-guard decisions, direct-evaluated at
  pack time — a f32 guard could flip at the image edge and jump σ by
  the full edge density). Sim verdict: 5.8e-5 → **6.7e-7** on the same
  band. Shipped in this round with new packed params (compensated
  18/cell_mm, 12/cell_mm, mmpp/cell_mm pairs + the four guard bounds).
