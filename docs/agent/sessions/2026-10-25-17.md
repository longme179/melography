## Design (established in a bit-exact Python prototype, then ported)

The prototype lives outside the repo (`/home/z/my-project/scripts/`:
`a22_grain_fastpath_proto.py` + `a22_debug1..8.py`) — it ports the exact
Rust hash (mix32/hash4/RandStream), the exact full-model cell math, and
the exact §L gate estimators (48 µm aperture, radial PSD slope,
layer ρ, zoom), then designs and validates the fast field before any
Rust was written. Key prototype findings:

1. **Port validation** (phase 1): the full model reproduces the
   test-profile declared slope within the gate tolerance (−0.787 vs
   −0.869, −9.4 %); RMS calibration is exact (the Rust test's 1e-9
   contract reproduced); ρ exact. The five bundled stocks' declared
   psd_slope anchors are artist-authored and broader than their shipped
   fields at the gate scale (measured: mono −0.98 vs declared −0.85,
   cool −1.36 vs −0.82, pastel −0.20 vs −0.92, vivid +0.02 vs −0.95,
   warm −0.81 vs −0.88) — the §L letter targets the DECLARED value, so
   the fast field is tuned against declared (as the gate checks).
   Two debug detours that mattered: a splat bounds bug (dropped grain
   edges, −43 % variance) found via a brute-force gather cross-check;
   and a factor-2 frequency mapping bug in a throwaway debug binning
   (the gate port `psd_slope` was correct all along).
2. **Commutensurability is fatal**: first candidate families
   (Δ = 15/30/60/120 µm, then 17/34/68/136 µm) are small-rational
   multiples of the gate's 6 µm sampling grid — the sample phase locks
   to a short period, the measured spectrum develops holes, and fitted
   slopes go absurd (−3.4 … −5.1) regardless of weights. Single-octave
   slope sweep vs Δ (6 µm → ~0 … 17 µm → −5.0) located the usable base.
3. **The design that validates**: Δ = (8, 16, 32) µm (incommensurate
   with 6 µm), weights `(1, t, t)` with one parameter
   `t = clamp(−0.8931·psd_slope − 0.6782, 0, 0.45)` (fitted on the six
   in-family profiles), ±√3 uniform node marks (zero mean, unit
   variance — Gaussian second-order statistics without Box–Muller),
   Cholesky-mixed per layer, tent interpolation, per-pixel σ(D) at
   pixel centres, the full model's own calibration statistic, and the
   same k supersampling rule.
4. **Validated gate numbers** (deterministic — the prototype's math is
   bit-portable to Rust, no libm in the fast path): slope test −0.832
   (4.2 %), mono −0.926 (9.0 %), cool −0.778 (5.2 %), pastel −0.910
   (1.1 %), vivid −0.956 (0.7 %), warm −0.848 (3.6 %); RMS at
   0.3/1.0/1.6 within ±4.1 %; ρ within 0.004 (mono ρ = 1.0 — the
   physically correct single-layer behaviour; its declared identity
   off-diagonal 0 is an M2 authoring artifact, the full model also
   renders ρ=1 for mono); zoom −2.5 %…−3.5 %.

## Rust implementation (crates/film)

- `FastGrain` (grain.rs): `FAST_DELTAS_MM = [8, 16, 32] µm`,
  `FAST_TAG = 0xFA57` (different field than the full model at the same
  seed — pinned by `fast_and_full_are_different_fields`),
  `FastNodes` strip-local per-octave node caches (absolute lattice
  indices → byte-exact under any tiling), `eval_at` with fixed
  octave/node summation order, `aperture_sigma_on_uniform` = the full
  model's 320²@6 µm grid + 8×8 boxes (the same one-step exact
  self-calibration), `apply()` with the identical strip contract and
  the same `k = clamp(round(mmpp/0.006), 1, 4)` sub-sampling;
  `margin_px = 0` (the fast path reads only its own rows).
- `GrainStage` enum (`Full | Fast`) with `resolve/ enabled/ margin_px/
  apply` dispatch; `chain.rs`: `FilmChainParams.grain_fast` +
  `with_grain_fast()`; `ChainStages.grain: GrainStage`.
- Wiring: `EditorState::film_leg()` and `stock_thumbs` set the flag
  (preview-class renders); the render cache key is unchanged (the flag
  is a renderer property, constant across preview renders); export
  (`export.rs` → `cmd_film_apply` → CLI) and the CLI never set it —
  the reference path stays the full model by construction.
- UI: "grain (fast preview)" hint in FilmLab when a stock is active and
  grain intensity > 0 (EN/VI i18n; parity + contrast audits covered by
  the existing scripts).

## Honest notes

- The §4 re-pin needs the owner's machine (sandbox has no cargo); the
  perf legs print both threading-only and threading+fast numbers so the
  A2.2 delta is directly readable.
- Node-cache scratch at preview scale is ~18 M nodes/image across the
  three octaves ([f64;3] each, per-strip caches) — preview-only; export
  and the memory-budget suites never run the fast path. An f32 node
  cache is a noted follow-up if telemetry ever shows pressure.
- Reachable spectrum band ≈ [−0.75, −1.5] of declared psd_slope;
  out-of-family authored profiles get the closest reachable spectrum +
  the label + the exact export (documented in FILM_MODEL §G).
- Mono's declared ρ off-diagonal 0 vs rendered 1 is a pre-existing M2
  profile-data artifact (monochrome ignores ρ); noted, not changed
  here (profile data changes are a separate decision).
