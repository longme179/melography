# MELOGRAPHY fuzz battery

Issue #25 · ARCHITECTURE §9 ("Fuzz (cargo-fuzz at M1+): decoders, LUT
parser, sidecar deserializer").

## Targets

| Target | Entry under test | Notes |
|---|---|---|
| `decode_image` | `melography_io::decode::decode_bytes` | The SAME S0 sanitization `decode_file` runs (bomb guard, ICC, orientation, RGB-f32). Header-dimension harness clip at 8 MP — see the target's module docs for the honest rationale; the >300 MP bomb path is exercised for real. |
| `cube_parser` | `melography_lut::cube::parse_cube` | Strict `.cube` validation. |
| `sidecar_json` | `SidecarV1::from_json` + `migrate` + re-serialize | The load→save→load roundtrip resumes and autosaves perform. |
| `manifest_json` | `ModelManifest` parse + `vet` | ADR-0004 gate — "ambiguous weights = rejected", never a panic. |

## Running locally

```sh
rustup toolchain install nightly
cargo install cargo-fuzz --version 0.13.0 --locked
cd fuzz
cargo fuzz run <target> corpus/<target> --release -- -max_total_time=60
```

Copy the corpus to a scratch dir first if you do not want new units
landing in the committed tree (CI does exactly that):

```sh
cp -r corpus/cube_parser /tmp/corpus && cargo fuzz run cube_parser /tmp/corpus -- -max_total_time=60
```

## Seeds

`corpus/<target>/` holds the committed seed set:

* `cube_parser` — the 30 adversarial cases from `crates/lut/tests/fuzz_corpus`
  (invalid sizes, NaN/Inf entries, UTF-16 BOM, CRLF truncation, …).
* `decode_image` — tiny deterministic PNG/JPEG/TIFF/WebP images,
  regenerated by `scripts/gen_fuzz_corpus.py` (dev-only Pillow; binary
  seeds carry sibling provenance records, verified by
  `scripts/provenance_check.py`).
* `sidecar_json` / `manifest_json` — valid + gate-relevant JSON shapes
  matching the real schemas.

## CI

The `fuzz-burst` job runs a short time-boxed burst per target on
ubuntu-latest with the seed corpus copied to a scratch dir. A crash
fails the job and the artifact is uploaded (14-day retention). No
silent crashes, no silent skips.
